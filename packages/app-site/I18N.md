# App site i18n

`@tomokichi/app-site` provides the shared localization foundation for app brand sites.

## Principles

- Each app chooses its own supported languages.
- The translation registry is the source of truth for supported locales.
- The default locale is served at `/`; additional locales use `/{locale}`.
- Header, mobile navigation, footer language switchers, canonical URLs, `hreflang`, and Open Graph locale metadata all use the same locale list.
- Existing EN/JA brand sites remain compatible through the legacy `enPageHref` / `jaPageHref` props while they are migrated.

## Add a language to a migrated app site

1. Copy an existing translation file, for example `src/i18n/en.ts` to `src/i18n/fr.ts`.
2. Translate every value while keeping the same keys. The `AppSiteTranslation` type checks the key shape.
3. Register it in `src/i18n/index.ts`:

```ts
import { defineAppI18n } from "@tomokichi/app-site/i18n";
import en from "./en";
import fr from "./fr";
import ja from "./ja";

export const i18n = defineAppI18n({
  defaultLocale: "en",
  translations: { en, ja, fr },
});
```

There is no separate supported-languages array to keep in sync. `supportedLocales` is derived from the translation keys.

## Per-app language choice

A site that registers only `{ en, ja }` shows only English and Japanese. A different site can register `{ en, ja, ko }` or any other set independently.

Locale display metadata is available for common languages through `localeMeta()`. Custom labels can be supplied with the optional `localeMeta` field in `defineAppI18n()`.

## Routing

The app-site template serves the default locale from `/` and generates non-default localized routes from `i18n.supportedLocales`. Existing `/ja` template routes are retained for compatibility; newly registered non-default languages are generated through `[lang]` routes.

When migrating an existing brand site, its page components should read copy from its `src/i18n` registry and pass `i18n.localeLinks(page)` to `AppSiteShell`.

## Shared links

`tmkch.io` itself currently supports English at `/` and Japanese at `/ja`. If an app site supports another locale, links to the operator/support site intentionally fall back to the English route until that destination gains the same locale.

## Language switchers

`AppSiteShell` renders a dropdown in three places whenever more than one locale is available:

- desktop header
- mobile navigation
- footer

All three navigate to the equivalent logical page in the selected language.
